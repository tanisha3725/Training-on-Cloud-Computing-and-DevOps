# 📘 DAY 2

## GitHub Workflow and Collaboration

Today, we explored how developers collaborate on GitHub. We learned about forks, clones, branches, commits, pushes, pull requests, and merging changes.

## GitHub Workflow

1. **Fork:** Creates a copy of another repository under your GitHub account.
2. **Clone:** Copies a repository to your local computer.
3. **Branch:** Provides a separate line of development.
4. **Edit:** Changes the project files.
5. **Commit:** Records staged changes.
6. **Push:** Uploads commits to a remote repository.
7. **Pull Request:** Proposes changes for review.
8. **Merge:** Integrates changes into a target branch.

## Branching in Practice

We explored how developers can create a feature branch, modify files without directly changing the main branch, and merge the changes after review.

We also learned about viewing commit history to understand the changes made to a project.

## GitHub Desktop

GitHub Desktop provides a graphical interface for common Git operations, including cloning repositories, viewing modifications, committing changes, managing branches, and synchronizing with GitHub.

## Fork Synchronization and Submodules

- **Sync Fork:** Helps update a fork with changes from the original repository.
- **Git Submodule:** Allows one repository to reference another repository at a specific commit.

- Practised or studied common Git operations through GitHub Desktop.
- Understood fork synchronization and the purpose of submodules.
